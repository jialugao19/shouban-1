核心结论：当前策略差，不是“仓位还不够灵活”这么简单，而是 隔夜段 alpha 本身为负，同时
sbgk 这一路径被高估、排序器解释力偏弱、组合暴露仍然偏高，三者叠加导致持续亏损。

先看证据。最新 run 的结果在 report.md 和 metrics.yaml：baseline_t1_open 的
ann_return=-0.5274, sharpe=-1.1665，但 baseline_t0_open_close 的 ann_return=0.3685,
sharpe=0.7208。这说明问题不是“不会选强票”，而是“选到的票隔夜留不住溢价”。而且这不是单年
失效，2021-2024 四年全部为负，2022-2024 更差，说明当前逻辑对不同市场阶段都缺乏稳健性。

第二个问题是 sbgk 明显在拖后腿。当前 path_mix 里 sbgk 占比约 57.5%，见 picks.yaml。但按
真实成交后的 T+1 open 收益拆分，sbgk 的单票平均收益大约 -0.54%，而 sbdk 和 rzg 都略正。
这说明现在不是“三条路径都不行”，而是 sbgk 的定义或打分方向有系统性偏差。更糟的是，sbgk
的平均 score_total 还是三者里最高，说明排序器在奖励错误的东西。

第三个问题是排序器本身弱。按实际成交样本看，score_total 和 T+1 open 收益的相关性只有大
约 0.03，五分位收益也没有稳定单调性，高分组并没有显著更好。这意味着当前模型虽然能把票排
出一个顺序，但这个顺序对隔夜收益几乎没有解释力。你这次新增的 limit_quality 确实有增量信
息，高分组的平均收益约 -0.396%，好于低分组约 -0.542%，但它只是“少亏一点”，并没有扭转主
信号为负的事实。

第四个问题是组合层还在放大错误暴露。虽然现在 avg_gross_exposure 已经降到约 0.709，比以
前满仓好，但 coverage 仍然有 0.886，而且大多数有仓日的总暴露仍接近 0.8。这意味着只要隔
夜 alpha 为负，组合层仍会持续、稳定地把这种负 alpha 放大成净值下行。

还有一个工程/研究层的问题需要单独指出：现在 baseline 和 score_threshold 的结果完全一
样，不是因为阈值设计成功，而是因为当前主配置已经是 dynamic_k_by_score=True，而且每天入
选票的最低分都已经在 0.55 以上，所以这个“对照组”已经失效了。也就是说，你现在的评估里少
了一个真正的 baseline，这会让后续判断改进是否有效变得不干净。

我建议的改进顺序是：

  1. 先修评估基线。
     把真正的 baseline 改回“dynamic_k_by_score=False、不做 score threshold、只保留 path
     cap 和 limit-up filter”的版本。否则你后面每次实验都不知道收益改善是来自“选股更准”还
     是“对照组定义变了”。
  2. 优先重构 sbgk，不要先全局调权重。
     当前最该怀疑的是 sbgk 的 open band、auction shape 和 strength 定义在奖励“高开易兑现
     票”。建议先做三个小实验：

  - sbgk 完全关闭，看组合是否显著改善。
  - path_cap_sbgk 从 2 压到 1 或 0。
  - 对 sbgk 增加更严格的尾盘封单稳定性和次日低开容忍度约束。
    如果这一步有效，再谈细调权重。

  3. 把特征重点从“强不强”转到“隔夜能不能留住”。
     现在 limit_quality 是对的方向，但还不够。后面应优先补这些更贴近隔夜溢价的特征：

  - 尾盘最后 30/60 分钟封单稳定性。
  - 首次封板后炸板次数与最后一次回封位置。
  - 次日开盘前可预见的兑现风险 proxy。
  - 分路径 regime 特征，比如大盘弱势时直接关闭 sbgk。

  4. 组合层继续收缩，而不是急着做更复杂的仓位优化。
     在主信号仍为负之前，不要做太复杂的连续权重。更有效的是：

  - 把 daily_gross_exposure_cap 先从 0.8 降到 0.4-0.6 做网格。
  - 让 sbgk 单独用更高阈值。
  - 对 rzg/sbdk/sbgk 分别设置 threshold，而不是共用一个 0.55。
